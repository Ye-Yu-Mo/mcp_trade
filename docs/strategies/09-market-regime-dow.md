# MR · 市场状态过滤（道氏理论 v1）

> 触发标签：`MR-v1`　｜　适用：**所有策略的前置开关**　｜　状态：待启用（0 笔）

## 一、为什么需要它

2026-10-27 的一天里，同一个 TB 策略在震荡市亏了 1.5R。**问题不是策略，是把趋势策略用在震荡市。**

道氏理论给的是最朴素的判定：**趋势 = 更高的高点 + 更高的低点**。本策略把这句话变成开关。

## 二、判定规则（1h 周期，每个标的独立计算）

```
前 3 个摆动高点和前 3 个摆动低点：
  全部抬升 → 上升趋势（TREND_UP）
  全部下移 → 下降趋势（TREND_DOWN）
  交替        → 震荡（RANGE）
```

摆动点定义：3 根 K 线的局部极值。

## 三、策略开关表

| 市场状态 | 允许策略 | 禁止策略 |
|---|---|---|
| **TREND_UP** | `TB`（做多）、`WY`（Spring 做多） | `RF` 做空（逆势） |
| **TREND_DOWN** | `TB`（做空）、`SMC` | `RF` 做多 |
| **RANGE** | `RF`、`SMC`、`LC` | `TB`（突破在震荡市经常失败） |

**这条规则如果早一天生效，ETH 突破那笔（-0.50R）会被拦下**——当时 BTC/ETH 都在 1h 区间内。

## 四、多标的确认（道氏理论的第二条）

道氏要求"指数互相确认"。加密市场用 **BTC + ETH 同向**作为确认：

| BTC | ETH | 结论 |
|---|---|---|
| 同向趋势 | 同向趋势 | 确认，可放大仓位 |
| 一趋势一震荡 | — | 只用基础仓位 |
| 两者相反 | — | **不开新仓** |

## 五、与 24h 涨跌幅的关系

不要用"24h 涨跌"判断趋势——它只看一个点。摆动点结构看的是**过程**。

## 六、执行方式

每次开仓前必须先输出：

```
MR: BTC=TREND_UP ETH=TREND_UP 一致 → 允许 TB 做多
```

如果状态是 RANGE 而我想做 TB，就必须在日志里写明理由——**默认不允许**。

## 七、已知局限

- 摆动点识别在剧烈波动时会频繁重绘
- 1h 状态和 4h 状态可能冲突 → **一律以 1h 为准**，4h 只作参考
- 震荡市识别滞后：通常在区间后半段才识别出来

## 八、启用条件

不需要历史标注，规则本身就是客观的。**下一笔交易开始强制执行**，并在每笔日志里记录 MR 状态。
